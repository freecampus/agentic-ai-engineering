FreeCampus Agentic AI Engineering

Contribute a Reproducible Learning Lab

Turn a planned lesson into reviewed instruction without weakening its checks.
Course progress 0%

1. Choose one planned outcome

Use the tracked catalog, unit overview, and outcome map to find the owning unit, stable lesson ID, intended scope, and expected learner evidence. All PLAN*.md files are ignored local material, not prerequisites for contributing, running tests, or building the site. If a maintainer supplies a local PLAN-LESSONS.md, also use its detailed teaching brief and lab checks. Keep the current task narrower than its unit outcome. Do not turn all 101 outlines into thin published pages.

When using that local tracker, maintain the task’s development status, owner, date, blockers, and evidence. Explicitly run poetry run makim plan.refresh and poetry run makim plan.check after updates. These commands need the local plan; CI and normal pytest runs do not read it. CI tests the validator using synthetic records and checks public curriculum relationships using tracked sources. A finished brief is not an implemented lesson; unit gates and capstone stages are tracked separately. Development state does not replace catalog publication state or imply verified learner completion.

The source layout keeps QMD under docs/courses/agentic-ai-engineering/, reusable Python under src/freecampus_agents/, and tests under tests/. This adapts the draft plan’s illustrative nested layout to the existing repository’s package structure.

2. Make the task runnable without a paid provider

Supply synthetic or openly licensed fixtures, a deterministic fake boundary, and machine-checkable ordinary and failure cases. Keep tool permissions and budgets explicit. Record observable events and concise rationales, not private reasoning. Never redistribute secrets, private data, or unlicensed recorded responses.

3. Author the lesson, not just its summary

Include a concrete task, 3–5 opening questions, a measurable outcome, active-time estimate, explanations, predictions, controlled changes, and debugging practice. Use three small checkpoints for concept, evidence, and failure diagnosis; give plausible distractors and explanations. Finish with a checked lab and primary references. Overviews stay quiz-free; planned project outlines are not assessments.

Unit challenges take 90–180 minutes and include a contract, progressive checks, three hint levels, injected failures, a hidden solution, and an evidence record. The templates are scaffolds outside the rendered course, not publishable lessons.

4. Keep publication records synchronized

When a lesson is genuinely available, update its catalog status, front matter, course progress IDs, available counts, outcome map, and sidebar together. Add the Colab include and a unique notebook path. Never link a planned path that does not exist. Do not enable whole-course completion until the completion contract is ready.

5. Check from a clean environment

Use Poetry 2.4+ within the 2.x series. A tracked poetry.lock now exists; validate it against pyproject.toml with poetry check --lock --strict before installation. If they disagree, review and regenerate the lock through the dependency-maintenance workflow, not by hand or by borrowing another course’s lock. Explicit CI lock enforcement and clean supported-platform installation evidence remain release work. A passing metadata check alone does not establish a fully reproducible release.

Conda + Poetry are required locally and in CI. conda.yaml supplies Python 3.12, Poetry, Node.js, and pip. Poetry installs project dependencies directly into the activated Conda environment. The shared poetry.toml disables separate virtual environments; the environment check rejects nested venvs or mismatched tools. Use poetry install, not synchronization, to preserve Conda-owned tooling. Activate the environment in each terminal and select its Python in your editor. Pre-commit hooks use these installed tools rather than creating hook environments.

conda env create -f conda.yaml  # First setup only
conda activate fc-agentic
python scripts/check_environment.py
poetry check --lock --strict
poetry install --all-extras --with docs
python scripts/check_environment.py
poetry run pytest -q
poetry run ruff check src tests scripts
poetry run ruff format --check src tests scripts
poetry run mypy src
poetry build
poetry run makim docs.build
git diff --check
poetry run makim clean.tmp

The build renders HTML, exports notebooks, and verifies expected output files. Open at least one desktop and narrow-screen quiz when browser tooling is available. Restart the smoke notebook and run from the top. Report skipped checks and external limitations rather than treating unrun checks as passing.

6. Keep current-system examples reproducible

Teach the transferable mechanism in the small course runtime first. The tracked docs/courses/agentic-ai-engineering/_technology.yml is a research register, not an installed dependency list or additional lesson catalog. It records the owning lesson IDs, accountable maintainer, primary sources, documentation review date, next review, known specification revision, and integration-validation state. Its initial entries are not validated integrations: no tested product version or execution evidence is implied by a documentation review.

Recheck each entry at least every 90 days and before authoring or publication. Review immediately after a relevant security advisory, breaking change, deprecation, or license/provider-policy change. CI checks register structure and lesson ownership offline; it cannot verify that a human reviewed a source or that an upstream service is still compatible.

Before supporting a live integration, record its exact release/commit, SDK and protocol revision, model revision, effective configuration, operating system, execution boundary, resource budget, and licensed fixture provenance. Preserve ordinary, denied-action, and held-out results plus independent review and an exit/rollback path. Set a validated version only when those artifacts exist. Do not use a floating latest or a vendor benchmark as execution evidence. Withhold or replace integrations whose maintenance or safety assumptions fail.

Use the case study appropriate to the engineering question

  • Skills: teach instruction packaging, selective loading, provenance, and review separately from tool authorization. The Agent Skills specification documents the format; host support for experimental permission metadata can differ.
  • OpenClaw: use architecture/configuration inspection for persistent assistants, then optional isolated operational experiments after Units 15–16. Its documentation states that sandboxing is off by default and that one gateway assumes a trusted boundary, not hostile multi-tenancy. Sandboxing and security guidance.
  • Hermes Agent by Nous Research: study the distinction between factual memory and reusable procedures, then compare no skill, a reviewed skill, and a generated skill on held-out tasks. Changing a skill is not training model weights or proof of improvement. Skills documentation.
  • Serving engines: verify a maintained vLLM or SGLang release for a new lab; retain TGI as a legacy/migration comparison following the upstream maintenance notice.

These source observations were reviewed on 2026-09-19; reverify before use. Early lessons use synthetic documents and sanitized architecture examples, not live assistants. Actual product execution is optional after the safety units, inside a disposable verified boundary with restricted mounts/egress, reviewed skills, synthetic identities, resource limits, and approvals. Do not require personal accounts, credentials, unattended host access, or paid services.

Every lab distinguishes course fixture execution, analysis of recorded observations, and optional live integration. A Colab replay is a useful free learning route but cannot establish OS containment, real-model learning gains, deployment reliability, or hardware performance. Keep the evaluator and held-out answers outside the agent’s writable boundary. Use observable actions and concise external rationales, never private chain-of-thought.

Substitute focused cases rather than silently enlarging lesson workloads. The published effort range is provisional: pilot the active work and account for milestone refinements, reviews, and optional setup separately.

Use the repository contribution guidance and Poetry’s basic usage for further detail.
